## 5. このセッションで分かった落とし穴（ドキュメント未反映のもの）

- **Supabase のアクセストークンにはスコープがある**（Project / Organization / legacy）。他人が作ったプロジェクトは、同じ Org でも読めないことがある
- **`supabase link` は 1 プロジェクトしか覚えない。** `scripts/db.mjs` は実行後に必ず staging へ link を戻す設計だが、**現状 prod/staging の定義が逆**（上記）
- **Google Cloud の新 UI（Google Auth Platform）は公開にホームページ URL とプライバシー URL を必須化**している。`vercel.app` のサブドメインは承認済みドメインにできない（所有証明不可）。独自ドメイン（#102）が無いと**新規の OAuth アプリは公開できない**。旧 UI で公開済みの SnowHam さんのアプリは影響を受けていない
- 上記により、あなたの Google アカウントに作りかけの Google Cloud プロジェクト（ブランディング途中）が残っている。**使わないので放置か削除**
- **Supabase の DB パスワードリセットはダウンタイムなし**（公式）。反映に数分かかることがある
- `gh` CLI は `gh auth login` 未実施。git の資格情報マネージャーからトークンを引く（前回メモ参照）。**この方法は API 呼び出しには使えるが、`gh secret set` のような一部コマンドは使える**（今回 `SUPABASE_PROJECT_REF` の更新に使用）
